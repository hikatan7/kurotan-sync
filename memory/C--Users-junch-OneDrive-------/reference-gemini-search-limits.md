2026-08-31、Claude（くろたん）がChrome拡張でGeminiに直接聞いて得た自己申告。詳細は `自作ファイル集\プロンプト集\01_横断検索と素材収集.md` の「件数の上限」節と「捏造を止める出力形式」節。

| 項目 | Geminiの回答 |
|---|---|
| 1回で扱えるテーマ数 | 1テーマ（単一PICO） |
| 網羅と精度の境界 | 5〜10件。15件超で確率的補完が始まる |
| 書誌情報の正確な出力上限 | 5〜8件。40件は「完全に非現実的」 |
| 「2巡して」の指示 | **通常チャットでは効いていない**（擬似的な思考ステップのみ）。Deep Researchでは内部ループあり |
| PubMed/PMC | 直接叩いていない。一般ウェブ検索インデックス経由でMeSH検索不可 |
| 医中誌Web | 検索不可（J-STAGE等のOAは可） |
| 本文到達率 | ペイウォール論文は抄録のみ。全体として抄録止まりが多い |

**Why:** ユーザーは「捏造しない・再検証する」と何度指示しても直らないと訴えていた。原因は不服従ではなく構造。Gemini本人の説明＝「コンテキストに生データが無いとき、空白やエラーではなく、それらしいタイトルやPMIDの形式を確率的に合成する。『作るな』という指示は確率の重みに影響するだけ」。さらに「生成した内容を自分で問い直しても、**同じ確率空間で判定するため誤りを真実と誤認し続ける**」＝**自己検証は原理的に不可能**。

**How to apply:** 指示の文言を強めるのをやめ、**出力の形式**を変える。①1回5〜10件・1テーマに分割（20件要るならテーマを4分割） ②症例数などは**抄録の原文をそのまま引用**させ、要約・言い換えを禁じる ③各項目に **[検索で確認] / [知識ベースからの推測]** の出所タグを必須化して、推測分を可視化し人間が潰す。自己検証には期待しない。検証は必ず外部（Claude のWebSearch/WebFetch、またはユーザーがPubMedで開く）で行う。

**自己申告の扱い：** これは実測ではなく本人の申告なので鵜呑みにしない（[[feedback-copilot-instruction-training]] の訓練0と同じ原則）。ただし実測とは符合する — 43件を一度に要求して5件（11.6%）が実在せず。一方で残り38件中9件は実在確認済みなので**真の上限は5〜8件より高い**。運用は安全側に倒して1回10件・1テーマ。関連: [[feedback-verify-ai-supplied-urls]] [[workflow-cross-site-search]] [[project-rats-research-plan]]


## ChatGPTにも同じ質問をした（2026-08-31追記）

chatgpt.com は**拡張で操作可能になっていた**（2026-07-05の「完全拒否」記録は古い）。ただし**ChatGPTの composer は英数字を落とす**ので、漢数字を使い、英字（PubMed・PMID等）は単独の type アクションで打つこと。送信ボタンは本文が伸びると位置が下がるので座標を取り直す。アカウントは**無料版**（Plus未加入）。

| 項目 | Gemini | ChatGPT |
|---|---|---|
| 1回のテーマ数 | 1テーマ | 1〜3推奨 |
| 正確な書誌の上限 | 5〜8件。40件は非現実的 | 10本安全／20本現実的／40本も出せるが全実在は保証しない |
| 「2巡して」 | 効いていない | 効くが不十分（自分の候補を自分で再確認するだけになる） |
| Deep Researchのページ数 | 数十〜100程度 | **わからない**。「数字を言うAIがいたら根拠を確認せよ」と警告 |
| 自己検証 | 原理的に不可能 | **独立した検索工程を挟めば条件付きで可能** |

**Why:** 数字が食い違うので、**どちらの自己申告も仕様として信用してはいけない**。信用できるのは両者が一致した4点＝①件数でなくテーマで分割 ②自己検証だけでは不十分で外部一次情報が要る ③指示の文言ではなく出力形式を変える ④要求件数を埋めるために水増ししない。これは実測とも合う（43件要求で11.6%が偽物、ただし外部から誤りを名指しすると自ら3件追加削除した＝ChatGPT側の説明が実態に近い）。

**How to apply:** 文献台帳を作らせるときは `01_横断検索と素材収集.md` の「検証プロトコル（ChatGPT提案）」を貼る。肝は**候補と検証済みを完全に分離し、UNVERIFIEDを許容すること**。全部埋めさせる表を渡すから捏造が起きる。空欄を許せば埋まらない行が可視化されて人間が潰せる。件数は「実在確認できた数」で報告させる。


## Copilotにも同じ質問をした（2026-08-31追記）

copilot.microsoft.com も**拡張で操作可能になっていた**（chatgpt.com と同様、2026-07-05の「完全拒否」記録は古い）。**Copilotの入力欄も英数字を落とす**ので、漢数字を使い英字は単独の type で打ち、落ちた語は補足行で再掲する。

| 項目 | Gemini | ChatGPT | Copilot |
|---|---|---|---|
| 1回のテーマ数 | 1 | 1〜3 | **1〜2。3以上で精度急落** |
| 書誌の正確な上限 | 5〜8件 | 10安全/20現実的/40は保証不可 | **わからない。40件は非現実的** |
| 検索経路 | 一般ウェブ検索 | タスクによる | **Bing一択。PubMed直接検索は不可** |
| 医中誌 | 不可 | 保証できない | **不可（クローズドDB）** |
| 本文到達 | ペイウォールは抄録のみ | 文献ごと | **本文は読めていない。スニペット・構造化データ・冒頭のみ** |
| 捏造対策の提案 | 出所タグ＋原文引用 | 3段階分離＋VERIFIED/UNVERIFIED | **「要確認」欄を必須＋DOIなしは出力禁止** |

**Why:** Copilotは3者で最も制約が厳しく、同時に最も正直に申告した。Bingのスニペットしか見ていないと自認しているため、**査読論文の書誌を作らせるのが最も危険**。

**How to apply:** **Copilotに文献台帳を作らせない。** 用途は Bing が厚くインデックスしている**公開行政文書（厚労省・デジタル庁・個人情報保護委員会・自治体）・学会ガイドライン本体・診療報酬の告示/通知/疑義解釈・公的統計**に限定する。専用プロンプトは `01_横断検索と素材収集.md` の「Copilot用プロンプト」節。**1回1テーマ**を厳守する。Copilot発案の**「要確認」欄必須**は他AIにも流用価値あり（生成で補った項目を隠せなくなる。空欄禁止、補っていなければ「なし」と書かせる）。関連: [[feedback-copilot-instruction-training]]
