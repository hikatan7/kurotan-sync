「レセプトデータ作る君_最終版検証中.xlsx」に **「総額明細」（印刷用・A4縦2頁）** と **「明細作成」（全行照合の作業用）** を新設(2026-07-28)。従来の 抽出結果→費用明細→検算→印刷用総括 は無改変（費用明細は68行上限・×行のみ）。

**総額明細の構成**: ①総額サマリー（DPC包括／出来高／請求点数／食事／入院総額を点数と円で）②入力・検証（包括点数・請求点数・食事は基本情報から自動、無ければ黄色セル手入力。出来高+包括=請求点数を自動判定）③出来高の区分別内訳（手術/輸血/麻酔/処置/検査・病理/画像/投薬/注射/薬剤/材料/医学管理/入院料/リハ/放射線/その他評価料/区分不明/**OCR未取得・未照合分**＝レセ記載との差を明示して合計が必ずレセと一致）④算定明細（1行＝1算定、内訳列にマスター照合した中身を「本体72,640点／超音波3,000点／自動縫合器2,500点×5」の形で連結、内訳合計とレセ点数の一致を✔判定）。

**明細作成の主要ロジック(隠し列)**: ページ番号AT→ページ点数計が既出ページと一致したら**ページ単位で重複除外**AU（同じページを2回貼っても二重計上しない）／グループ番号AV（＊行・区分番号行で開始、×行で終了＝レセの1算定単位）／採用フラグBP（コードあり＆グループ内同一コード未出＆確定or手入力or候補≤3件or部分≤3件）／グループ内running集計 AY(S点数) AZ(薬材円) BA(内訳テキスト) BB(区分記号) BG(件数) BQ(代表名称)。表示名は**グループ先頭の実質行**（＊n日・区分番号行を除く。×行はOCR貼付H列の名称候補）を優先＝マスター名より正確。区分は マスターの区分記号(s_マスターCG列: K手術/L麻酔/N病理…、K92は輸血)→無ければ診療識別(160→60等)にフォールバック。

**照合の追加ルール(誤マッチ対策)**: 「：」を含む行と「（」で始まる行はコメント行として照合対象外（せん妄対策のコメント行が「ハイリスク分娩管理加算」に誤マッチした実害あり）。前方一致ラダーは L=24/20/17/14/12/10/8/6 と、**5文字は候補3件以下のときだけ**採用（「自動縫合器使用加算」→「自動縫合器加算」を拾うため）。

**Excelの落とし穴(実測)**: `SUMPRODUCT(MAX(LEN(range)))` は暗黙の交差で #VALUE! → **`AGGREGATE(14,6,配列,1)`** ならCSE不要で配列評価される。PowerShellは ’ “ ” を引用符と解釈するので数式に入れない。`"$41:$41"` のような文字列は $4 が変数展開されるのでPrintTitleRowsは単引用符で渡す。`$ex.Calculation` はブックを開く前に設定不可、`CutCopyMode=0` は型変換エラー、veryHiddenシートは Visible=-1 にしないと Delete できない。**COMビルドを再実行すると「使い方」への追記が重複する** → 再実行時は追記前に同一文言行を掃除すること。

**2026-07-29: 費用明細の繋ぎ替え＋非表示、新OCRフォーマット対応** — 表示シートは 使い方／OCR貼付／印刷用総括／総額明細／基本情報／明細作成／点検結果 の7枚（費用明細・抽出結果は非表示、計算は継続）。**費用明細I列(マスターコード)を明細作成の「グループ代表コード(BU列＝グループ内で最初に確定した行のコード)」から自動取得**するようにした → 併算定チェック(背反・包括)と算定回数チェックが手入力なしで働く。抽出結果B列(名称候補)も明細作成BQ(代表名称)を参照させ、**「←前行参照・要確認」表示を解消**（印刷用総括の名称も改善）。費用明細N列の回数チェックは「算定単位=日 かつ 回数≦在院日数」なら警告しない。※I列は数値で返すこと（テキストだとマスターのMATCHが効かず「未登録」になる）。

**新OCRフォーマット（項目名・規格・数量が別行、罫線区切り、【見出し】、ローマ数字）対応**: ①照合キーで**ローマ数字Ⅰ〜Ⅹ→1〜10**変換（マスター側にローマ数字は0件なのでクエリ側だけでよい）②罫線行(─━―＝)・【見出し】行でグループを区切り、代表名称の候補からも除外（次頁/続く/ページ/K514形式の区分番号行も除外）③**数量が次行にある形式に対応**（同一行で取れなければ次の1〜2行を見て、残り文字が単位ホワイトリスト(瓶管筒袋錠個枚本包キットA V T C…、明細作成BZ列)に一致する場合のみ採用。mL/mgは規格なので不採用）④確定判定に**一致長≧クエリ長×45%**を追加（「ヘパリンNa注5千単位…」がS区分の「ヘパリン」に誤確定するのを防ぐ）。**注意: OR()の中でCODE(LEFT(x,1))を使うと空文字で#VALUE!（OR は全項を評価する）→ 入れ子IFにすること**。

**入退院日がExcelシリアル値のOCRに対応(2026-07-29)**: 「今回入院年月日」の次行が `46106` のような**5桁のExcelシリアル値**で出力されるOCRがある(46106=2026/3/25)。基本情報B8/B9に「和暦テキストが取れなければ 基本情報抽出F14/F15 が40000〜60000ならシリアル値として採用」のフォールバックを追加 → 在院日数B10・総額明細A2・印刷用総括B8が自動で埋まる。日付表示は `TEXT(...,"ggge年m月d日")` で和暦に統一。印刷用総括B8は診療実日数が空なら「・診療実日数日」を出さないよう修正。

**タイトル自動生成(2026-07-29)**: 総額明細A1(20pt太字)＝`【傷病名】ロボット支援下 主たる術式　入院n日間`。総額明細の隠し列で算出: AH3=手術区分行の最大小計／AH4=その行の明細名称／AH5=OCR全文に「支援機器/ロボット/ダビンチ」があれば"ロボット支援下 "／AH6=連結。AF3=HCU日数(明細名称に「ハイケア」かつ「加算」を含まない行の回数合計)、AG3=ICU等日数(特定集中治療室/救命救急/脳卒中ケア/小児特定集中)、AF4/AG4=OCR全文の記載有無 → 点数行が無いときは「HCU 記載あり(日数不明)」と表示。A2に入院期間・在院日数・HCU/ICU・DPC・年齢。印刷用総括A1にもHCU/ICUを追記。**総額明細の検証行は「明細化できた出来高＋包括 vs レセ記載請求点数」を比較する**(出来高を請求点数−包括で定義したため、単純比較だと恒等式になり無意味だった)。

**重大: 貼り付けで解析数式が消える事故(2026-07-29)** — ユーザーがOCR貼付シートを全選択クリアしてから貼り直したため、**C〜I列の解析数式(正規化/×位置/回数/単価/連番/名称候補/DPC行)が400行すべて消失**し、明細が全部0になった。対策として**解析数式を「OCR解析」シート(veryHidden)に分離**し、OCR貼付はA列に貼るだけの純粋な入力欄にした。参照は `Cells.Replace` で `OCR貼付!$C`〜`$I` → `OCR解析!$C`〜`$I` に一括付け替え(A列参照は変えない)。以後どう貼っても壊れない。

**推定補完機能(2026-07-29)**: ①**中間部分一致(tier D)** — 前方一致で拾えないOCR誤字を `MID(キー,3,20/14/10)` の部分一致で救済(例「キノプロフェンナトリウム錠60mg「日医工」」→ロキソプロフェン…)。照合列は「中間」表示。②**点数行が無いまとまりを薬価から推定** — 【使用薬剤】ブロックのようにレセプトに点数記載が無いグループを、マスター薬価×数量から点数換算して算定明細に出力し「推定(レセに点数記載なし)」と表示・薄青で色分け。**推定の条件は「グループに×行なし かつ 照合済み品目2件以上 かつ 最初の点数行より後」** — この3条件が無いと、DPC分類欄の術式名や【手術・処置等】の入力情報まで算定として二重計上する(実際に+64,002点の過大計上が出た)。③区分別内訳の最終行を「OCR未取得分（入院基本料等加算・特定入院料などと推定）」とし、合計が必ずレセプト記載の出来高と一致するようにした。④薬剤・材料金額計は採用行(BP=1)のみ集計 — 誤マッチの高額品(アイリーア117,440円)が混入していた。

**HCUの既定日数=1(ユーザー提供の運用ルール, 2026-07-29)**: 胸腔鏡下・ロボット支援の肺葉切除では**HCUは1日までしか算定できない**ため、点数行が無い場合は1日で固定してよい。総額明細のG13(黄色・変更可)=HCU日数、G14=マスター193512510「ハイケアユニット入院医療管理料１（１４日以内）（ＤＰＣ）」5,035点/日、G15=推定計上点数(明細からHCU日数が取れた場合は0にして二重計上を防ぐ)。区分別内訳の「入院料等（うちHCU推定 n点）」に加算し、残差行と検証文が自動で連動する。

**残る限界**: 「麻酔管理料（Ⅰ）」＋次行「（閉鎖循環式全身麻酔）」のように種別が次行にある項目は候補3件から誤選択しうる（→手入力コードで確定）。手術本体も候補7件で内訳から除外される。使用薬剤ブロックに点数行が無いOCRでは「OCR未取得・未照合分」に集約される。
