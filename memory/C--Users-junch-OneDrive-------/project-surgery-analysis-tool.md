デスクトップ「手術件数推移」フォルダに **手術分析ツール.xlsm** を構築・実データ検証済み (2026-07-19)。

- **データ**: 同フォルダの「*手術実績*.xlsx」(2024/2025/2026年_匿名化、計13,924件・2024/01～2026/06)をマクロ「全分析更新」が自動取込→②データに統合(派生列: 年月/年度(4月始)/曜日/時間帯/緊急/ロボット/手術時間分/麻酔時間分)。
- **シート構成**: ⓪使い方(ボタン) ①設定(黄色セル=ロボット判定KW・緊急区分・注目診療科・実行ログB23) ②データ ③月別推移 ④手術室別 ⑤緊急手術 ⑥診療科別 ⑦ロボット ⑧注目診療科(=呼吸器外科) ⑨追加分析定義。
- **拡張の仕組み**: ⑨に1行(有効○/分析名/行項目/列項目/集計値/フィルタ×2/グラフ種)追加→「追加分析のみ実行」で「追加_分析名」シート+グラフを自動生成。フィルタは*ワイルドカード対応。L列に実行結果表示。
- **集計ルール**: 緊急=時間外+深夜・休日(空欄は「未分類」扱い、2024-25年は空欄約1200件/年あり)。ロボット判定=術式に「ロボット支援」or「支援機器」(StrConv vbWideで全角半角同一視)、「支援加算」除外。検証値: ロボット計645(泌尿器172/呼外171/消外169/産婦133)、緊急413、呼外622(ロボ率27.5%)。
- **VBA**: modUtil/modImport/modStd/modCustom/modMain(cp932 .bas、スクラッチパッド作成)。RegExp不使用・Collectionキーでインデックス管理。名前定義 SRG_AUTOMODE があるとMsgBox抑止(COMテスト用、納品時は削除済み)。
- **構築手順の実績**: openpyxlで土台xlsx→PS+Excel COMでVBComponents.Import+ボタン追加→SaveAs 52→Application.Runでテスト→Python(openpyxl+NFKC正規化)で30ヶ月分の件数照合全一致。AccessVBOM=1だった(ユーザーが前回から戻し忘れ)。
- **月次運営報告書モジュール追加(2026-07-19)**: ⑩報告書(BSC4視点KPI+信号判定+診療科増減ランキング術式ドライバ付+A4印刷設定)/⑪ヒト分析(部屋×曜日・時間帯ヒートマップ・部屋別コア稼働率)/⑫カネ分析(科別・術式別推定手術料、機会損失)を「報告書生成」マクロ(modReport)で生成。⑬手入力KPI(オペラマスター転記: 直介Ns不在/麻酔種別/カテ室件数/緊急件数/予実差異13科×11区分マトリクス)・⑭アクションログ(PDCA、未完了行を⑩へ自動転記)・⑮点数マスタ(885術式をs_20260501マスタと自動マッチ、要確認142/未マッチ27、件数カバー98.7%)・⑯報告設定(対象月/コア時間8:30-17:15/時間外単価6000円/時)。②データは21列に拡張(手術・麻酔の開始終了時刻)。
- **短手3注釈(2026-07-19)**: ⑮点数マスタH列に短期滞在手術等基本料3対象を「○ K634」形式で注釈(32術式・延べ1,709件、区分番号+限定条件の名称ルール判定、低信頼マッチ経由の誤判定はスコア85未満除外で対処)。主要対象: K634腹腔鏡下鼠径ヘルニア両側752件/K282白内障PEA 348件/K616-4シャントPTA 166件/K633鼠径ヘルニア103件。
- **データの癖**: 台帳出力はカテ室が不完全(2026/06はデータ17件vs実54件)、「緊急区分」は時間外区分のみで真の緊急件数(55件)と別概念 → 両方⑬転記優先。手術室件数はコンサル報告と±2件で一致(2026/06: 528 vs 530)。
- **教訓追加**: VBAは識別子が大文字小文字非区別 → Const MAXD と Function MaxD が重複宣言でコンパイルエラー→モジュール全体のマクロが実行不可になる(「マクロを実行できません」)。NumberFormatは英語書式必須([赤]→[Red])。COMで保存済xlsmを開いてRunするには Application.AutomationSecurity=1 を Open 前に設定。孤児Excel(VBEタイトル)がファイルロックする→ Get-Process excel 全停止。
