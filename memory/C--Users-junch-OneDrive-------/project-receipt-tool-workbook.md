デスクトップの「**レセプトデータ作る君_最終版.xlsx**」(36MB・34シート)が最新(2026-07-17)。**入力例は削除済みで未入力(真っさら)状態**(ユーザー要望)。未入力時は検算シートに「(未入力)」と表示される。PQ接続なし=openpyxl編集可。旧版: v3(OCR取込まで)、v2(保存不全の可能性・削除推奨)、試作品(ユーザー原本・PQ接続あり)。個別レセプトの成果物は「レセプト明細_令和8年3月分.xlsx」。

**最終版の追加機能:** 支払基金の医科歯科全マスター24ファイルを内蔵(補助/包括/背反1-5/入院基本料/算定回数/b_傷病名/hb/ikou/c_コメント/f_歯式/s_20260501/t_20260227/y_20260317)+ソート済み「背反キー」(93,114行)・「包括キー」(280,373行)。「併算定チェック」シート=費用明細I列のコード同士を40×40マトリクスで背反・包括判定(TEXT9桁連結キーの二分LOOKUP)。費用明細L/M/N列=算定回数テーブルの単位・上限・超過チェック。テスト実績: 初診料×外来リハ1→背反2件、A000001×皮膚科特定疾患指導管理料→包括1件を検出。

**構成:**
- 可視シート: 使い方 / 基本情報(総括表転記+DPC包括・食事の検算) / **OCR貼付**(メモ帳のOCR全文をA3に貼付) / **抽出結果**(「点数×回数」行を数式のみで自動抽出→確認後、費用明細へ値貼り付け2回) / 費用明細(1行=1「点数×回数」、区分別小計、マスター照合列I〜K) / 検算(①出来高+包括=請求点数 ②DPC=日当点×日数×係数 ③食事) / コード表 / ホーム・照合結果・照合結果2(ユーザー既存)
- **veryHidden**: s_20260605(診療行為)・t_20260529(特定器材)・y_20260522(医薬品)マスター。Power Query接続付き → **openpyxlで再保存禁止**。編集はExcel COM経由で。
- OCRパーサーはレガシー関数のみ(ASC/DBCS/LOOKUP/FIND等、マクロ不使用)でオフライン・全Excelで動作。テスト実績: 本レセプト2〜3枚目で29行・119,465点を漏れなく抽出。
- 入力例: 令和8年6月分・右下葉肺癌(DPC 040040xx02x0xx)・5日入院。出来高120,220点+包括25,018点=請求145,238点で検算一致。

**基本情報自動読取(2026-07-17追加):** OCR全文(1枚目含む)をOCR貼付に貼るだけで、「基本情報抽出」シートがキーワード検索(MATCHワイルドカード)で請求点数・負担金額・食事・DPC日当点/係数/包括・入退院日・傷病名等を自動抽出し、基本情報の青字セルに数式で流し込む(手入力上書き可)。明細側はDPC包括行など「=を含む計算行」を自動除外。**数式の落とし穴(実測):** ①`FIND({"0".."9"})`等の配列定数はCOM .Formula の通常入力では配列展開されない→10項の明示MINで書く(LOOKUPの引数内は配列評価されるのでOK) ②日本語ExcelのVALUEは「8年6月5日」を日付(2008/6/5)として解釈→日付は年月日マーカー基準で桁抽出 ③JISの英語名はDBCS ④ASCは濁点カナを2文字に分解し位置がズレる。

**新OCR形式対応(2026-07-17夜):** ①×行名称が加算(縫合器/超音波/周術期口腔)なら直前3行の非抽出「手術」行名を前置連結(標本行は除外) ②DPCが1行3×型(入I…入II…合計…×係数=包括)でも係数=検出行のE列・包括=「=」直後から取得 ③食事ラベル「食事療養費: 690円×11回」対応(基準row kw=基準/食事療養費)。※デスクトップのマスターはロック中でSendUserFileで送付済み — 次回デスクトップ版が最新か要確認(scratchpad final_full.xlsxが正)。ユーザーOCRプロンプトの残課題: 麻酔管理料と周術期加算の点数重複/材料の個別+合計二重/酸素8点に×1なし/処方2×20に=付き。

**まとめ点数の加算注記(2026-07-17):** OCR貼付H列が、抽出行の±数行(r-3..r+1)から自動縫合器/超音波凝固/周術期口腔のキーワードを検出し、名称に「（＋◯◯加算を含むまとめ点数）」を自動追記(自行に同語があれば重複回避)。K514-22の構造: 手術本体72,640点(ロボ支援も同一点数)+自動縫合器2,500×個数。6月=+5個+超音波3,000=88,140 / 3月=+8個+口腔200=92,840 / 4月=+6個=87,640。

**4月練習データ検証(2026-07-17):** ユーザーはOCRプロンプトで練習レセプトを生成中(保存先: デスクトップ\病院経営学\診療報酬点数\レセプト作る君詳細版)。AI生成レセプトには架空の算定エラーが混ざる(自動縫合器加算への点数重複記載、器材点数行の欠落、「2×20=40錠」形式、ラベル揺れ「総点数」「一部負担金」)。Excel側は「総点数/一部負担金」kw追加・「8点×1」対応済み。**注意: 注記文に「87640×1」等のパターンを書くと再抽出される** — 修正文に点数×回数を含めないこと。OCRプロンプト改善提案済み(まとめ点数は1行のみ/器材は点数行必須/=以降禁止/食事の基準・食堂行必須)。

**タブ整理+点検結果シート(2026-07-17):** 可視タブ=使い方→OCR貼付→印刷用総括→基本情報→費用明細→点検結果 の6枚のみ。抽出結果/基本情報抽出/検算/併算定チェック/コード表=通常非表示(右クリック再表示可)、マスター26枚=veryHidden+Protect。「点検結果」=検算3行+併算定エラー一覧(マトリクス1600セルを隠しヘルパーH:K列で線形走査→背反はi<jで重複除去、包括は方向保持)+回数上限超過一覧を自動集約。

**タイトル術式自動判別(2026-07-17):** 印刷用総括H2がOCR/費用明細のキーワードから術式を判定(優先: 支援機器orロボット→「ロボット支援手術」>胸腔鏡>腹腔鏡>縦隔鏡>区分50あり→「手術」>なし)しタイトルに組込み(例:【右下葉肺癌　胸腔鏡手術入院5日間】)。A1直接編集で上書き可。

**完全自動化(2026-07-17最終):** 費用明細A/C/D/E列は抽出結果から数式で自動反映(コピペ転記は廃止)。OCR貼付に貼るだけで 基本情報→費用明細→検算→印刷用総括 まで全部つながる。手入力上書き可(式が消える点は使い方に記載)。practice形式でエンドツーエンド検証: 検算3OK・差異0・印刷1ページ。

**次行フォールバック(2026-07-17追加):** OCRが「ラベル行↵値行」形式(例: 「請求点」の次の行に「145,238」)でも読めるよう、基本情報抽出はS(同一行)/T(次行・空行スキップ)/U(数字有無)/J(採用)の構成。テキスト値(I列)も同様の次行フォールバック。両形式でテスト済み(ラベル+値行形式は差異0で完全一致)。ユーザーのOCRプロンプト出力(practice_notepad.txt形式)は高品質でそのまま使える。

**印刷用総括シート(2026-07-17追加):** 検算の後ろに「印刷用総括」— タイトル自動生成(A1・手書き上書き可)+基本情報+明細40行(項目名120字で省略)+DPC計算+区分別小計+総費用サマリを全数式参照で構成。A4縦・FitToPagesWide=1/Tall=3設定済みでそのまま印刷可(実測2ページ)。※デスクトップの最終版がExcelで開かれていて上書きできず、SendUserFileで送付済み — 次回セッションでデスクトップ版が印刷用総括を含むか要確認(scratchpadのfinal_full.xlsxが最新だがセッション限り)。

**Why:** ユーザー(医療従事者)がオフライン環境でもレセプトから入院総費用を明細化できるようにするため。

**How to apply:** 新しいレセプト画像が来たら: 画像から「点数×回数」行を費用明細に、総括表の値を基本情報に転記 → 検算3チェックすべてOK=正確、の基準で報告。式をCOMで書く際の注意: JISはDBCS、全角カナの濁点はASCで2文字になり位置がズレる(位置計算は正規化後文字列基準で)。デスクトップのファイルはExcelで開かれているとロックされる — 上書き前に排他アクセス確認、ダメなら別名配置。環境は[[env-word-com-doc-generation]]参照。
